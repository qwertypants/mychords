> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a mobile-first guitar chord reference where people audition exact voicings, arrange them into named song sections, and save songs in their browser.

**Architecture:** A static React application owns a versioned local song library. A bundled chord catalog provides fingerings; both SVG diagrams and acoustic sample playback consume the same absolute string/fret coordinates. Song editing uses immutable commands and persists only after validating storage on startup.

**Tech Stack:** Vite, React, TypeScript, native Web Audio API, localStorage, @dnd-kit/core and @dnd-kit/sortable, Vitest, Testing Library, Playwright. Resolve compatible stable dependency versions during setup and commit the lockfile.

## Confirmed intent and implementation assumptions

The user confirmed this is a reference app for composing, not a practice sequencer. There are songs, ordered sections, and ordered chord occurrences. Every occurrence stores the exact selected voicing. Repeated chords and repeated names are allowed. Previewing a chord never silently adds it to a song.

Implementation defaults, adjustable during review: standard six-string EADGBE tuning, frets 0–22, portrait-first interface, fixed short sequence spacing, explicit Save with a dirty indicator. Preview a section or the whole song once; no rhythm editor, looping, metronome, or accompaniment. Sections play in their displayed order. Changing songs with unsaved edits offers Save, Discard, and Cancel.

“All chords” is a breadth requirement, not a claim that a finite library contains every theoretical chord or every physically possible fingering. Include the complete source catalog, its slash chords and extended qualities, plus octave-shifted versions within fret 22. Publish an audit of actual roots, suffixes, positions, gaps, and rejected records. Never advertise universal coverage or hide missing positions. If the imported catalog cannot meet useful low/middle/high neck coverage for the common chord families, resolve those gaps before release instead of reducing the requirement silently.

### Design decision

Use a bundled, audited voicing database rather than generating arbitrary combinations of chord tones. It supplies known fingerings and avoids presenting unplayable shapes. Algorithmic enumeration could be more exhaustive but needs a separate playability model; a remote lookup service adds connectivity and provider dependence. Neither is necessary for this reference app.

Use bundled sampled acoustic guitar notes rather than oscillators. This gives acoustic timbre and keeps runtime requests on the site's own origin. Native Web Audio provides the small amount of scheduling needed without a sequencer framework.

### Screen behavior

- Library: saved song names, New song, and Open. Empty state explains where songs are stored.
- Song editor: editable song title, named section list, Add section, Save status, Play song and Stop.
- Section: editable name, Play section, remove confirmation, Add chord, ordered chord cards with handles and Move earlier/Move later buttons.
- Chord picker: searchable name, root and quality filters, neck-position filter, available voicings, labeled diagrams, separate Hear and Add buttons. Picker is a full-height panel on phones; a side panel on larger displays.
- Selecting Add appends to the active section and keeps the picker available. Close restores focus to Add chord. Dragging changes order only; tapping Hear does not reorder or select another voicing.
- Touch targets at least 44 CSS px; visible keyboard focus; labels and live announcements; page scroll works outside drag handles. No page-level horizontal scrolling at 320 CSS px.

## Shared contracts

Define these contracts in Tasks 1–3 before UI wiring; retain these names throughout.

```ts
// src/chords/types.ts
export type Six<T> = readonly [T, T, T, T, T, T];
export type Voicing = {
  id: string; root: string; suffix: string; label: string;
  frets: Six<number>; // absolute frets, low E through high E; -1 = muted
  fingers: Six<number>; // 0 = open/muted; 1–4 = finger
  barres: readonly number[]; // absolute fret numbers
};
// src/songs/types.ts
export type ChordEntry = { id: string; voicingId: string };
export type Section = { id: string; name: string; chords: ChordEntry[] };
export type Song = { id: string; name: string; sections: Section[]; updatedAt: string };
export type Library = { version: 1; songs: Song[] };
// src/audio/guitar.ts
export type PreviewItem = { entryId: string; voicing: Voicing };
export type PlaybackState = {
  status: 'idle' | 'loading' | 'playing' | 'error';
  activeEntryId: string | null; message: string | null;
};
export interface GuitarPlayer {
  play(items: readonly PreviewItem[], onState: (s: PlaybackState) => void): Promise<void>;
  stop(): void;
  dispose(): void;
}
```

Catalog references are immutable and IDs encode canonical root, suffix and absolute fret vector, not array indexes. Library references must resolve against the bundled catalog on load. Missing IDs are an explicit recoverable error; preserve the stored bytes and do not substitute a different shape.
